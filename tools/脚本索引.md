## 一、编译与验收（每次改完代码都跑）

### build.ps1 — 编译两版（命令行版 + 界面版）
```powershell
pwsh -NoProfile -File tools\build.ps1     # 实际就这一条；版本号从项目根 VERSION 文件读，发新版改那个文件
```
- **注两个值进 exe**：`BuildStamp`（编译时刻）与 `BuildVersion`（读项目根 `VERSION`，当前 1.0.4）；界面底部显示「版本 x.y.z · 本版编译于 …」，老板和我都能一眼确认跑的是哪一版。
- **每次要上正式版先升 `VERSION`**（老板 2026-10-28 指出「这次版本号都没改」）：改了代码要发出去，就先把项目根 `VERSION` 往上加（修 bug/加功能至少 +0.0.1），再编译、再覆盖正式版。只改编译时刻不算升版。
- **坑**：脚本里先 `Set-Location` 到 `app` 目录才读 VERSION，**路径必须写死成绝对路径**（写成相对会读到 0.0.0，踩过）。
- **界面版必须带 `-H=windowsgui`**，否则双击会多开一个黑控制台窗。
- 编译前跑：`gofmt -w .` → `go vet ./...` → `go test -count=1 ./internal/...` → `node --check frontend\dist\app.js`。

### run-gui.ps1 — 启动**测试版**并回标题（只杀测试版，不碰老板的正式版）
```powershell
pwsh -NoProfile -File tools\run-gui.ps1          # 普通启动（-id catherder-dev -label「…（测试版）」）
pwsh -NoProfile -File tools\run-gui.ps1 -Debug   # 启动并跑界面自检（结果进日志，用 read-log.cjs 读）
```
- **两份并存（2026-10-26）**：老板挂后台的正式版用 `-id catherder-formal`，我用 `-id catherder-dev`；**锁号不同才能同时跑**（Wails 单实例锁 UniqueId 相同会把第二份并进第一份）。末尾会列出在跑的每份并标 `[正式版]/[测试版]`。
- **杀进程只按命令行特征杀**（`-match 'catherder-dev'`）：原来按进程名 `Stop-Process` 全杀，会误杀老板那份。
- **并存必须各指各的库**（`--data`）：两份共用同一个 SQLite 会抢同一张任务单（引擎取任务没有认领锁）。

### make-desktop-release.ps1 — 把当前版发到桌面当正式版（独立锁号/名字/库）
```powershell
pwsh -NoProfile -File tools\make-desktop-release.ps1   # 编译完再跑；复制 exe + 建快捷方式
```
- 产出：`C:\Users\Administrator\Desktop\墨云(OpenClaw)\工头派工台 正式版\catherder-gui.exe` + 同目录快捷方式「工头派工台 正式版.lnk」，参数 `-id catherder-formal -label「工头派工台 CatHerder（正式版）」-data <该目录>\catherder.sqlite`。
- **能验出什么**：回复制的 exe 大小/时间、快捷方式路径、参数、库位置。
- **坑**：跑之前必须先 `build.ps1`（否则发的是旧版）；截图目录跟 `--data` 走，会自动落在同目录，不用另配；开机自启注册表值**没改**（仍指 workspace 那份，改它属系统级高危要先问老板）。
- **两版都必须带 `-tags production`**：不带时 exe 能起来但**开不了界面**——界面版表现为「启动即退」（无窗口、无报错，因为 `-H=windowsgui` 把那句提示也吞了）。拿不定就用**命令行版** `bin\catherder.exe` 跑一下：它会把「这个 exe 编译时没带 production 标记，开不了界面」直接打印出来。
- 界面版另需 `-tags wv2runtime.browser`（本机走 WebView2 运行时）。
- **必须用 `Invoke-CimMethod` 起进程**：`Start-Process` 起的 GUI 进程有时拿不到窗口。
- 进程秒退先怀疑编译标记（见上一条），别先去猜代码坏了。
- 命令行里带引号的路径**先存进变量再拼**，直接写 `'"'+(Get-Location).Path+'"'` 在哈希表里会被 PowerShell 解析错（踩过）。

### i18n 脚本组 — 界面语言（中英切换）的抽取/分类/自查
```powershell
node tools\i18n-extract.cjs html app\frontend\dist\index.html   # 抽界面文案（属性值+标签间纯文本）
node tools\i18n-extract.cjs js app\frontend\dist\app.js app\frontend\dist\shot.js
node tools\i18n-classify.cjs            # 前端含中文的行分类：注释/界面/日志/待定 → tmp\data\i18n-lines.txt
node tools\i18n-writesites.cjs          # 列出 app.js 里所有「往界面写文字」的位置（接 tr() 用）
node tools\i18n-goscan.cjs              # Go 侧（internal/ 下 .go，排注释与 _test）中文字符串去重清单 → tmp\data\i18n-go.txt
node tools\i18n-logscan.cjs             # 写进事件日志的中文文案（.Log/logEvent 里的字面量）去重清单 → tmp\data\i18n-log.txt
node tools\i18n-logtest.cjs             # 拿真实格式日志行喂 trLog，看句子翻没翻、窗口名/路径/报错有没有保住原文
node tools\set-editing.cjs --id 35 --on   # 把某条排队任务直接置成「正在改」（或 --off 改回排队）：验「正在改的跳过、后面照常派」用
#   验派发跳过：先 `catherder.exe add <窗口key> 正文` 造两条，`set-editing.cjs --id 第一条 --on`，再 `catherder.exe tick --dry`
#   该看到「[试运行] 将把 第二条 派发给 …」+「排队任务暂未派发：有一条正在就地修改，先跳过它」
node tools\i18n-check.cjs               # 自查词典：tr() 引用有没有漏登记 + 静态页英文界面下残留几段中文
```
- **能验出什么**：`i18n-check` 回「词典 N 条 / tr() 引用 N 条 / 漏 0 条 / 静态页残留 0 段」——改完文案跑一下，不为 0 就是漏翻。`i18n-goscan` 用来划清「哪些中文在 Go 侧」：只有**托盘菜单/悬停/气泡、系统文件框与另存为框**必须在 Go 侧改（`internal\app\i18n.go` 的 `uiT()`）；其余经 `feed` 到界面的，**登记进前端词典就翻，Go 一行不用改**。
- **坑**：
  - 词典按长度从长到短整段替换，**长句要先登记**（短句会把长句切碎）；语言下拉要打 `data-no-i18n`，否则「中文」会被「中」→Medium 换成「Medium文」；`i18n-check` 模拟翻译时要跟 `i18n.js` 一样跳过 `data-no-i18n`，不然报假残留。
  - 带窗口名/通道名的句子走 `i18n.js` 里的 **RULES**（整句正则换英文语序）。规则里抓出来的窗口名/通道名**必须用 `keep()` 藏成占位符**再过片段词典——不藏的话「飞书群」会被短词条「群」换成「飞书group」；括号里的**原因文字**（「N 条任务均为异常」）要翻，用 `keepText()`（藏起来、放回时再过一遍词典）。
  - 在 Go 侧 `uiT()` 翻的词，**前端不能再拿原文做字符串比较**（附件检查「发不出去」、服务状态「模型服务空闲/繁忙」都是这种），所以这类词只在显示层翻。
  - **日志页走另一条通道 `trLog()`**（日志是已存进库的历史，Go 不改）：`[前端]` 开头的调试行整行原样不翻；类别名查 `LOG_KINDS` 表；正文里「图标」这类词**必须先登记整句**，否则会被短词条「图」换成 img（自检抓到过：在任务栏img标区）。括号里的原因走 `keepText()`——放回时**只走整句规则不走片段词典**，否则「3 条任务均为异常」会被换成「队列Medium 3 items…」。
- 文案清单落盘：`tmp\data\i18n-html.json`、`i18n-js.json`、`i18n-lines.txt`、`i18n-go.txt`（别把原文读进对话）。

### 自动关机这一块的验法（老板 2026-10-28 提的两个问题）
```powershell
node tools\peek-shutdown-log.cjs 关机        # 正式版+测试版都查；时间按本地时区打印（谁何时下了关机、有没有被撤销）
node tools\peek-formal-shutdown.cjs         # 只读正式版：auto_shutdown / shutdown_hours / shutdown_armed_at 现值
node tools\poke-shutdown-state.cjs --auto 1 --hours empty --armed-ago 0 --gate-service 0 --gate-gpu 0 --include0 工头派工台
node tools\poke-shutdown-state.cjs --restore   # 测完必跑（auto=0、时段空、标记 0、两道闸门开、工头窗口重新勾选）
node tools\poke-setting.cjs ui_lang en        # 切英文（命令行版 set 会把后面的参数全拼成值，带 -data 时尤其容易写脏）
pwsh -NoProfile -File tools\click-gui-button.ps1 -Title '测试版' -Name '取消关机'
```
- **造「正在倒计时」的条件**：`--armed-ago 0` 写一个「就是现在」的准备时刻，再把两道闸门关掉、把**正在干活的这个窗口取消勾选**（否则它自己就挡住条件），等一轮（默认 60 秒）横幅就变成「准备关机，还剩 N 秒」。
- **真关机风险**：条件一直满足 + 缓冲走完 = 机器真关。测前先确认 `--armed-ago` 给足余量，**测完立刻 `--restore`**；`armed` 只是「准备」，那条 `shutdown` 要到缓冲结束那一轮才下达，所以中途清掉标记就不会关机。
- **验「重启后不该继续挂着关机」**：`--armed-ago 120` 造一个残留标记 → `run-gui.ps1` 重启测试版 → `peek-test-log.cjs 关机` 应看到「撤销：程序重启，上次挂着的关机准备作废」、标记归 0、横幅回到「等条件满足」。
- **验「点了取消就立刻生效」**：造倒计时 → `click-gui-button.ps1` 点「取消关机」（记下时刻）→ 1 秒内 `window-shot.ps1` 拍图，横幅应已变成「等条件满足」（不能再有「还剩 N 秒」），日志里撤销那条的时间应与点击同一秒。
- **`click-gui-button.ps1` 自己的坑**：① UIA 的 Name 条件**不支持通配符**（`*测试版*` 匹配不到），脚本改成自己枚举子窗口用 `-like` 挑；② 托管 API 的 `Invoke()` **不收参数**（传 Point 报「找不到重载」）；③ WebView2 的网页元素要等 UIA 树建好才找得到，`NOTFOUND` 不等于按钮不存在。
- **`shutdown /f` 的官方语义**（`shutdown /?` 原文）：`/f Force running applications to close without forewarning users`，且「`/t` 大于 0 时才自动隐含 `/f`」—— 我们用的是 `/t 0`，所以**必须明写 `/f`**，否则有程序挡着时 Windows 会弹框等人点，命令已下达却一直没关。

### 截图层坑（改这块前先看）
- **「闪一下」的真凶是窗口底色**：Wails 全屏/退全屏那一瞬 WebView 重绘露出的是窗口底色，**默认是白** → 那一下白闪。修法：`main.go` 里 `BackgroundColour: &options.RGBA{R:0,G:0,B:0,A:1}`。注意它在 **`pkg/options`** 里（`options.RGBA`），**不在 `pkg/options/windows`**，写成 `windows.RGBA` 编译不过；alpha 不参与（只取 R/G/B）。
- **放大镜直接画在主画布上**（redraw 末尾按 `loupeAt` 画），**不要单独一个 canvas 元素 + 单独定位**——上轮就是那样，结果「拉框时出不来」。状态标记 `loupeInfo.shown` **每帧先复位再画**，否则拿着上一帧旧值报「还在」，探测就信了假。
- **马赛克是涂抹不是拉框，而且不要描边**：整屏先算一次马赛克图缓存（`mosaicImg`），**沿笔迹每一点放一个圆（arc）合成裁剪区再 clip**，只 clip 不 stroke。上轮拿 `strokeStyle='#000'` 描一条粗路径当裁剪区 → **黑色直接露出来就是老板看到的「黑框」**。圆圈大小跟「细/中/粗」变（半径 `size×3`）。出图时 `drawMarkAt` 要连 `ox/oy` 一起传，否则选区平移后马赛克错位。
- **「按住左键不出框、松手才出」＝绘制函数缺 `sel` 分支**：拖动中 `cur` 已传进 `drawMark`，只是 `tool==='sel'` 那一支不存在 → 什么都不画。**不是事件问题**，别去查鼠标。
- **顺畅靠「少画」而不是加缓冲**：`onMove` 里**挪不够 1 像素不记点也不重画**（点少一半）；放大镜每帧要取色，**1x1 探针画布必须只建一次**（每帧新建是白扔性能）。
- **文字要最简**：只 `fillText` 一个色，**不加描边（strokeText）、不加风格/外边**；落点直接挂在 `textEl.at` 上，**不要单独的 `editAt` 变量**。
- **按钮用标识不用文字**（老板 2026-10-26）：花圈✎ 椭圆◯ 方形▭ 箭头➚ 文字T 马赛克▦ 取色◎ 撤销↶ 重做↷ 清空🗑 另存为⤓ 完成✓ 取消✕，**中文说明放 `title` 里**（悬停可见，也不挡翻译）。
- **箭头是一种普通标注**：`drawMark` 加一个 `arrow` 分支（起点→终点一条线，末端按线方向画两翼，张角 ±30°、长度 `max(10, size×4)` 跟「细/中/粗」变）。**存盘/另存为/合成出图/撤销重做一行不用改**——`exportPNG` 走 `drawMarkAt`，对所有工具通用。新工具记得同步 `CURSORS` 表与选区上方那行提示。
- **验箭头别拿 mouseup 坐标算两翼**：mouseup 那一点**不会追加进 `mark.pts`**（笔尾是最后一次 mousemove），拿它算探点会探偏、报假的「没箭头」。**探点要用那一笔自己记的首尾点**（`mark.pts[0]` / `pts[pts.length-1]`）。更稳的独立复核：存出来的图用 `tools\peek-pixel.cjs` 读像素（标准库 zlib 解 PNG，不装 Pillow）。
- **截图层（`#shot`）在 `<div id="app">` 外面**，而 `i18n.js` 的 `applyDom()` 只走 `#app` → **截图工具条的悬停说明在英文界面下仍是中文**（13 条）。`i18n-check` 数的是整份 index.html，所以它报「残留 0 段」而界面实际是中文——**这个自查脚本查不到截图层**。要真验：`tools\peek-shot-tooltips.ps1`（读 UIA HelpText，就是悬停说明）。
- **马赛克圆圈光标跟粗细变**：`mosaicCursor(size)` 现给 SVG 光标（直径 `size×6`），**Windows 自定义光标最大 32 像素**，粗挡到底封顶；CSS 里不要写死一份。
- **验自定义光标别拆 `style.cursor` 的引号**：Chromium 会把 `"` 转义成 `\"`，拆不到就报「直径 0」（假报告）。**读 `getComputedStyle(canvas()).cursor` 并用 `/width=\?["']?(\d+)/` 取数**。
- **功能删除必须请示**（老板 2026-10-26 立）：没下令就不删、不改标识；同样代码能实现想要的功能时选简单办法，别复杂化。
- **「第二次才出问题」先查上一次收尾漏清了什么**：`endShot` 清了选区/标注/取色卡片却漏了「当前工具」→ 取色后 Esc 取消、再截图时工具还停在取色，按下只取色不框选 → 出不来框。收尾函数要把它管的状态**全清干净**；复位优先**复用现成入口**（`document.querySelector('[data-tool="pen"]').click()`），不新写一套切换。
- **没选区时按下必须先框选**：`onDown` 里 `!sel` 分支要排在 `tool === 'pick'` 之前；取色只在选区定完之后不受选区限制。
- **自检必须测「取消后再来一次」**（跨次场景）：单次流程测不出状态残留。看 `第二次截图：取消后工具=pen 颜色=#ff3b30 … 按下左键橡皮框已画出`。
- **取色器不要顺手改画笔色**（老板要「默认红」）：取到的色只亮在色块排里（`#shot-color-custom`），**要点一下才生效**；`endShot` 收尾要把工具与颜色都复位（工具点花圈按钮、颜色点红块按钮，复用现成入口）。
- **选中态样式要考虑「选中项本身就是白/近白」**：单圈白环在白块上等于没选中（老板报「点两回都是白色」）。用**深浅双环**：`border-color:#1b1f27; box-shadow:0 0 0 2px #fff, 0 0 0 3px rgba(0,0,0,.5)`。
- **打字中点工具栏按钮会被按下抢走输入框焦点** → 输入框 blur 落定甚至丢字。解法：**在按钮上加 `mousedown` 里 `preventDefault()`**（一行），**不要**给输入框加「失焦再抢回来」那种兜底。
- **探测点必须落在选区内**：选区外 `onDown` 直接 return，输入框根本不开，会报假「文字丢了」（本轮第一次自检就栽在 `vh*0.72` 落在选区外）。
- **Go 的 `time` 格式串必须用参考时间 `20060102-150405`**，写成 `20260102` 会输出字面量。`SaveFileDialog` **取消返回空串不是错误**，要当「没存」处理（截图另存为走 `SaveShotAs`）。
- **文字多点保留**：`commitText()` 不接坐标参数、用 `editAt`；正在打字时点到别处 → 先落定这段（保留）再在新点开输入框。**别加「空字抢焦点再抢回」那种兜底**（老板明确不要）。
- **老板的硬要求**：不要兜底/保护代码，功能要最简实现，不要屎山。
- **全屏时机**：`CaptureScreen` 只抓屏；全屏由界面在**黑底已盖住界面**之后调 `EnterShot`，退全屏后靠 `resize` 事件自己 `fitCanvas`。**已删掉 `settleSize` 轮询兜底**（老板：不要兜底代码）。
- Wails 的 `Fullscreen()` 会先 `SetMaxSize(0,0)`/`SetMinSize(0,0)` 再切；若还嫌闪，从这里查下去（不是再加一层保险）。
- **在画布上 focus 输入框要等一帧**（`requestAnimationFrame`）：同帧 focus 会被 mousedown 默认行为抢回画布 → 字打不上；输入框 z-index 要高于画布与工具栏。
- **SVG data-URI 光标**：`#` 要写成 `%23`、属性用单引号，否则光标加载失败退回默认十字。工具光标靠给 `#shot-canvas` 加 `cur-*` 类切，新工具记得同步 `CURSORS` 表。
- 顶栏自检：报品牌区/标签页/徐章的像素位置（比裁图可靠，窗口不够高时裁图会缺行）。
- 自检故意**不加入队列**：加入队列就会真发消息给目标窗口。

### 拖文件进来（Wails 拖放）的两个条件
- `main.go` 里要开 `DragAndDrop: &options.DragAndDrop{EnableFileDrop: true}`，Go 侧要 `runtime.OnFileDrop` 接事件。
- **可放的元素必须在 CSS 里声明 `--wails-drop-target: drop;`**（默认属性名/值写在 `pkg/options/options.go`）。不声明时拖进来**没反应**（webview 自己吞了），看起来像"拖放坏了"。自定义属性会继承，所以只给容器（`.composer`）声明就能覆盖它里面的子元素。
- 拖放高亮：Wails 自己给目标元素加 `.wails-drop-target-active`，跟着它加自己的样式即可，不要自己监听 dragover。

## 八、PowerShell 通用坑（本项目高频）

1. **带引号/JSON/正则/中文的一行命令 → 先落成 `.cjs` 或 `.ps1` 文件再跑**。一行里塞 `\"` 十有八九被吃（本轮又踩五六次）。
2. `Invoke-CimMethod` 的哈希表里**别直接写带引号的拼接串**，先存变量。
3. 读中文文件加 `-Encoding UTF8`，并先 `[Console]::OutputEncoding=[System.Text.Encoding]::UTF8`。
4. 单次工具输出**截断**（`Select-Object -First N`），日志先 `Select-String` 过滤再读。
5. 大文件（几百 MB 的 sqlite）**不能整块 `toString`**（node 上限约 512MB 字符串）：用 `Buffer.indexOf` 定位 + 分块切片。
